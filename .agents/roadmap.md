### 📦 Этап 1: База данных и Архитектура (Supabase)
* [x] **1.1. Схема данных пользователей и экономики:**
  * [x] Создать таблицу `users` (id, telegram_id, username, crystals, keys, energy_updated_at, created_at).
  * [x] Создать таблицу `user_stats` (связь с пользователем: путь Света/Тьмы, очки Отваги/Хитрости).
* [x] **1.2. Схема данных контента (Сюжет):**
  * [x] Создать таблицы `stories` (Сказки) и `episodes` (Главы).
  * [x] Создать таблицу `user_progress` (текущая история, пройденные узлы/ноды сюжета, купленные премиум-выборы).
* [x] **1.3. Безопасность БД (RLS):**
  * [x] Включить Row Level Security для всех таблиц.
  * [x] Настроить политики `deny-by-default` — пользователь может читать и писать только свой `user_progress` и `users` по `telegram_id`.

### 🔒 Этап 2: Бэкенд, Безопасность и Telegram Bot
* [x] **2.1. Криптография и Авторизация:**
  * [x] Реализовать жесткую валидацию `initData` от TMA через HMAC-SHA256 подпись токена бота.
  * [x] Запретить передачу скрытых полей (mass assignment) вроде `crystals` или `keys` при обновлении профиля клиентом. Все начисления валюты идут только через серверные функции.
* [x] **2.2. Webhook / Long Polling Telegram Bot:**
  * [x] Настроить обработчик команды `/start` для регистрации пользователя в БД и выдачи стартовых кристаллов/ключей.
  * [x] Добавить кнопку запуска Telegram Mini App (TMA).
* [x] **2.3. Serverless API Эндпоинты:**
  * [x] `GET /api/stories` — получение списка доступных историй и эпизодов.
  * [x] `POST /api/progress/save` — сохранение выбора в диалоге и обновление статов (Свет/Тьма/Отвага).
  * [x] `POST /api/ads/reward` — безопасное начисление +2 💎 после просмотра рекламы.

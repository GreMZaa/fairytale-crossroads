### 🎨 Техническая документация: UI/UX, Анимации и Рендер

**Контекст:** Мы создаем плавный, "дорогой" интерфейс визуальной новеллы на базе React.js и TailwindCSS[cite: 4]. Время первичной загрузки Mini App должно составлять строго < 1.5 секунды[cite: 3]. Все интерфейсы должны соответствовать принципам Apple HIG и Telegram Design System[cite: 4].

---

#### 1. 🎞 Плавные анимации (Framer Motion)
**User Flow:** Игрок нажимает кнопку выбора. Старый фон плавно затухает, новый появляется без резких скачков. Персонаж выезжает снизу экрана с легким покачиванием (эффект дыхания)[cite: 2].
**Acceptance Criteria (AC):**
*   Отсутствие резких скачков (layout shifts) при смене сцен.
*   Анимация провала (shake) при неверном выборе сопровождается красным свечением.
*   Сохранение 60 FPS на средних мобильных устройствах.
**Technical Considerations:**
*   Использовать библиотеку `framer-motion` для декларативного описания анимаций.
*   **Сайд-эффекты:** Анимации не должны блокировать основной поток выполнения (Main Thread).
*   **Data Schema:** Не влияет на схему данных напрямую, опирается на изменение состояния (state) в React-компонентах[cite: 2].

---

#### 2. 🥞 Слоистая архитектура рендера (Z-Index Layering)
**User Flow:** Игрок видит сцену, где задний фон находится позади персонажей, а элементы интерфейса (диалоги, кнопки) всегда перекрывают игровой мир[cite: 2].
**Acceptance Criteria (AC):**
*   Строгая иерархия слоев. Спрайты никогда не перекрывают диалоговое окно.
*   Поддержка темной и светлой темы для UI-элементов (Tailwind-классы `dark:bg-*`)[cite: 3].
**Technical Considerations:**
В проекте фиксируется жесткая система слоев (Tailwind `z-*` классов):
*   `Layer 0 (z-0)`: Задний фон (Background) — изображения в формате WebP.
*   `Layer 1 (z-10)`: Интерактивные предметы (Props).
*   `Layer 2 (z-20)`: Спрайты персонажей (Characters).
*   `Layer 3 (z-30)`: Игровой UI (Кнопки выборов, баланс кристаллов, диалоговое окно).
*   `Layer 4 (z-50)`: Глобальные модальные окна (Настройки, Покупка кристаллов).

---

#### 3. 📱 Глубокая интеграция Telegram Web App SDK
**User Flow:** Игрок запускает игру из бота, она открывается на весь экран. При нажатии на варианты ответов игрок чувствует легкую вибрацию. При случайном свайпе вниз игра не закрывается[cite: 1, 2].
**Acceptance Criteria (AC):**
*   Приложение автоматически вызывает `Telegram.WebApp.expand()` при старте[cite: 3].
*   Оверскролл (свайп вниз для закрытия окна) надежно заблокирован[cite: 1].
*   При нажатии на кнопки вариантов ответа срабатывает тактильный отклик (Haptic Feedback)[cite: 3].
**Technical Considerations:**
*   **Gestures & Swipe Protection:** Сэмулировать обработку события `touchmove` при `scrollTop === 0`, применяя `e.preventDefault()`, а также задать глобальный CSS `overscroll-behavior: none`[cite: 1].
*   **Инициализация:** Использовать `window.Telegram.WebApp.initData` для получения контекста, передавая его на сервер для обязательной криптографической валидации HMAC-SHA256 (защита от подмены пользователя)[cite: 1, 4]. Помечать серверные эндпоинты валидации тегом `@security`[cite: 2].

#### 4. ⌨️ Эффект «Печатной машинки» для текста
**User Flow:** Игрок читает реплику персонажа. Текст появляется посимвольно. Если игрок не хочет ждать, он тапает по экрану, и текст отображается целиком мгновенно[cite: 2].
**Acceptance Criteria (AC):**
*   Скорость вывода — 30-50 мс на символ.
*   Тап по блоку диалога мгновенно завершает анимацию (Skip).
*   При появлении символов воспроизводится тихий звуковой клик.
**Technical Considerations:**
*   Создать кастомный React-хук `useTypewriter(text: string, speed: number)`.
*   **Входные параметры:** `text` (строка для вывода), `speed` (задержка в мс)[cite: 2].
*   **Возвращаемые значения:** Текущая отображаемая строка, флаг завершения `isCompleted`, метод `skip()`[cite: 2].
*   Оптимизировать ререндеры, чтобы избежать лишней нагрузки на CPU.

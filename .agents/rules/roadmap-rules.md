### 🗺️ Roadmap: Сказки: Перекрестки Судеб (Telegram Mini App)

#### 📦 Этап 1: База данных и Архитектура (Supabase)
*   [ ] **1.1. Схема данных пользователей и экономики:**
    *   [ ] Создать таблицу `users` (id, telegram_id, username, diamonds, keys, energy_updated_at, created_at)[cite: 2].
    *   [ ] Создать таблицу `user_stats` (связь с пользователем: путь Света/Тьмы, очки Отваги/Хитрости).
*   [ ] **1.2. Схема данных контента (Сюжет):**
    *   [ ] Создать таблицы `stories` (Сказки) и `episodes` (Главы)[cite: 2].
    *   [ ] Создать таблицу `user_progress` (текущая история, пройденные узлы/ноды сюжета, купленные премиум-выборы).
*   [ ] **1.3. Безопасность БД (RLS):**
    *   [ ] Включить Row Level Security для всех таблиц[cite: 2].
    *   [ ] Настроить политики `deny-by-default` — пользователь может читать и писать только свой `user_progress` и `users` по `telegram_id`[cite: 2, 4].

#### 🔒 Этап 2: Бэкенд, Безопасность и Telegram Bot
*   [ ] **2.1. Криптография и Авторизация:**
    *   [ ] Реализовать жесткую валидацию `initData` от TMA через HMAC-SHA256 подпись токена бота[cite: 2, 4].
    *   [ ] Запретить передачу скрытых полей (mass assignment) вроде `diamonds` при обновлении профиля клиентом[cite: 4]. Все начисления валюты идут только через серверные функции.
*   [ ] **2.2. Webhook Telegram Bot:**
    *   [ ] Настроить обработчик команды `/start` для регистрации пользователя в БД и выдачи стартовых алмазов/ключей[cite: 2].
*   [ ] **2.3. Serverless API Эндпоинты:**
    *   [ ] `GET /api/stories` — получение списка доступных историй.
    *   [ ] `POST /api/progress/save` — сохранение выбора в диалоге и обновление статов.

#### 📱 Этап 3: UI-Кит и Движок Новеллы (Frontend TMA)
